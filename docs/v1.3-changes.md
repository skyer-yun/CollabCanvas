# CollabCanvas v1.3 — AI 设计智能增强 变更记录

## 变更日期

2026-06-03

## 变更概览

v1.3 让 AI 从"通用聊天窗口"升级为"理解项目设计系统的智能助手"。三个核心功能：AI 消费设计系统 Token、导入时提取设计特征、AI 输出设计质量检查。

灵感来源：[Axhub Make](https://axhub.im/make/) 的"主题即数据"（theme-as-data）和设计质量强制系统。Axhub 用 TreeWalker + getComputedStyle 提取设计 Token、30+ 反模式规则的多引擎检测、结构化 Export Pack 注入 AI prompt——v1.3 借鉴了前两者的核心思路，适配 CollabCanvas 的零构建纯 JS 架构。

## 详细变更

### 1. core/state.js — designProfile 状态字段

**位置**：`settings` 对象内，`ai` 字段之后

**新增**：

```javascript
designProfile: {
  colors: [],       // [{value, count}] 使用频率排序，最多 8 个
  fontSizes: [],    // [{value, count}] 最多 6 个
  fontFamilies: [], // [{value, count}] 最多 4 个
  spacing: []       // [{value, count}] 最多 6 个

```

**用途**：存储从已导入页面提取的设计特征，作为 AI 生成的风格参考。

---

### 2. main.js — 设计特征提取

#### 2.1 新增辅助函数 `_extractDesignProfile(html)`

**位置**：`_findFirstPage()` 之前

**算法**：
1. 创建临时 `<div>` 并填入 HTML
2. `querySelectorAll('[style]')` 获取所有有内联样式的元素（上限 500）
3. 遍历每个元素的 `style` 对象，按频率统计：
   - **颜色**：`color`/`backgroundColor`/`borderColor` 等 5 个属性，过滤 `transparent`/`inherit`/`none`/`initial`
   - **字号**：`fontSize`
   - **字体**：`fontFamily`
   - **间距**：`marginTop`/`marginBottom`/`paddingTop`/`paddingBottom`/`gap`/`lineHeight`，过滤 `0px`/`normal`
4. 每个维度按频率降序取 top N（颜色 8 / 字号 6 / 字体 4 / 间距 6）

**返回值**：

```javascript
{
  colors: [{value: '#1677ff', count: 12}, {value: '#333', count: 8}, ...],
  fontSizes: [{value: '14px', count: 20}, ...],
  fontFamilies: [{value: '"PingFang SC"', count: 15}, ...],
  spacing: [{value: '16px', count: 30}, ...]
}
```

#### 2.2 修改 `importPages()` — 导入后异步提取

**位置**：`importPages()` 的 FileReader `onload` 回调中，所有文件读完后（`imported === pending`）

**变更**：在 `bus.emit('page:imported')` 之后追加 `setTimeout` 异步提取：

```javascript
setTimeout(function() {
  var allPages = state.get('pages.list') || [];
  var allHtml = allPages
    .filter(function(p) { return p.type === 'page' && p.html; })
    .map(function(p) { return p.html; })
    .join('');
  if (allHtml) {
    var profile = _extractDesignProfile(allHtml);
    state.set('settings.designProfile', profile);
  }
}, 0);
```

**设计决策**：
- 使用 `setTimeout` 异步执行，不阻塞页面切换
- 合并所有已导入页面的 HTML 提取，而非仅最新一批，保证 profile 反映全局风格

### 3. ui/tabs/ai-tab.js — 设计智能四件套

#### 3.1 DS-01: `_extractDesignTokens()`

**位置**：`_executeCommand()` 之后，新增方法

**功能**：从 `document.documentElement` 的 computed style 读取 CollabCanvas CSS 变量

**采集范围**：

| 类别 | 变量 | 数量 |
|------|------|------|
| 颜色 | `--cc-primary` / `--cc-success` / `--cc-warning` / `--cc-error` / `--cc-text` / `--cc-bg` 等 | 15 个 |
| 圆角 | `--cc-radius-sm` / `--cc-radius-md` / `--cc-radius-lg` | 3 个 |

**返回值**：`{ colors: {'--cc-primary': '#1677ff', ...}, radius: {...} }`

#### 3.2 DS-01+02: `_buildDesignPrompt()`

**位置**：`_extractDesignTokens()` 之后

**功能**：构造设计系统 prompt 段落，注入 AI system prompt

**输出结构**：

```
## 设计系统 Token
本项目使用 CSS 变量体系。生成 HTML/CSS 时必须使用以下变量，不要使用硬编码值：

### 颜色（必须使用变量）
- --cc-primary: #1677ff
- --cc-success: #52c41a
...

### 圆角（必须使用变量）
- --cc-radius-sm: 4px
...

示例：使用 `color: var(--cc-primary)` 而非 `color: #1677ff`

## 项目风格参考（从已导入页面提取）
以下是项目中使用频率最高的设计值，请优先使用：

### 高频颜色
- #1a1a1a (使用 25 次)
- #1677ff (使用 12 次)
...

### 高频字号
- 14px (使用 20 次)
...
```

**注入点**：`_sendMessage()` 中 system prompt 末尾追加 `designPrompt`

#### 3.3 DS-03: `_buildTokenMap()`

**位置**：`_buildDesignPrompt()` 之后

**功能**：构建反向映射表——从 CSS 计算值（rgb/ hex）反查变量名

**映射策略**：
- `getComputedStyle(root).getPropertyValue('--cc-primary')` → `rgb(22, 119, 255)`
- 同时存储 rgb 格式和 hex 等价格式：`rgb(22, 119, 255)` → `var(--cc-primary)`, `#1677ff` → `var(--cc-primary)`
- 这样无论 AI 输出哪种格式都能匹配

**返回值**：`{ colors: {'#1677ff': 'var(--cc-primary)', 'rgb(22, 119, 255)': 'var(--cc-primary)', ...} }`

#### 3.4 DS-03: `_sanitizeDesignOutput(text)`

**位置**：`_buildTokenMap()` 之后

**功能**：后处理 AI 响应，替换代码块中的硬编码值为 CSS 变量

**算法**：
1. 正则匹配所有 ` ```lang ... ``` ` 代码块
2. 在每个代码块内，用 `_buildTokenMap()` 的映射表替换 hex 颜色
3. 只替换 `#xxxxxx` 格式的颜色（`computed.match(/^#[0-9a-f]{3,8}$/i)`）
4. 非代码块的文本不处理（保护 prose 不被误替换）

**示例**：
```
// AI 输出：
background: #1677ff;  color: #52c41a;

// 清理后：
background: var(--cc-primary);  color: var(--cc-success);
```

#### 3.5 新增工具函数 `_rgbToHex(rgb)`

**位置**：IIFE 内部，`_escHtml` 之前

**功能**：`rgb(22, 119, 255)` → `#1677ff`

**用途**：`_buildTokenMap()` 将 getComputedStyle 返回的 rgb 格式转为 hex，用于匹配 AI 输出

#### 3.6 修改 `_sendMessage()` — 注入设计 prompt + 清理输出

**变更 1**：system prompt 构造追加 `designPrompt`

```javascript
// 旧：
var systemPrompt = '...命令列表...\n';

// 新：
var designPrompt = this._buildDesignPrompt();
var systemPrompt = '...命令列表...\n' + designPrompt;
```

**变更 2**：AI 响应处理前增加清理

```javascript
// 旧：
var assistantMsg = { role: 'assistant', content: result.content, ... };

// 新：
var content = self._sanitizeDesignOutput(result.content);
var assistantMsg = { role: 'assistant', content: content, ... };
```

## 数据流

```
导入 HTML 文件
  → importPages() 读取文件内容
  → setTimeout 异步调用 _extractDesignProfile(allHtml)
  → 统计颜色/字号/字体/间距频率
  → state.set('settings.designProfile', profile)

用户在 AI Tab 发送消息
  → _sendMessage()
    → _buildDesignPrompt()
      → _extractDesignTokens() 读取 CSS 变量
      → state.get('settings.designProfile') 读取设计特征
      → 拼接为结构化 prompt
    → system prompt + design prompt → AI API
  → AI 返回响应
    → _sanitizeDesignOutput(result.content)
      → _buildTokenMap() 构建反向映射
      → 仅在代码块内替换硬编码 hex → var(--cc-*)
    → 清理后的内容存入会话 + 渲染到气泡
```

## 与 Axhub Make 的架构对比

| 维度 | Axhub Make | CollabCanvas v1.3 | 说明 |
|------|-----------|-------------------|------|
| Token 提取 | `TreeWalker` + `getComputedStyle` 遍历所有元素 | `querySelectorAll('[style]')` 仅扫描内联样式 | imported HTML 以 inline style 为主，够用；后续可升级为 TreeWalker |
| CSS 变量读取 | 遍历 `document.styleSheets` 找 `:root` 规则 | `getComputedStyle(document.documentElement)` | 效果等价，CollabCanvas 所有变量都在 `:root` |
| 设计质量检测 | 30+ 反模式规则 + 4 引擎 | 仅 hex→var() 后处理替换 | v1.6 目标：引入反模式注册表 |
| AI Prompt 结构 | Export Pack manifest + screenshot + topology | Token 表 + 频率统计 | 简洁有效，后续可加入截图引用 |
| 主题系统 | 100+ 品牌主题（DESIGN.md → theme.json → CSS vars） | 单套 CSS 变量 | 后续可扩展多主题切换 |

## 验证方法

### DS-01 验证：AI 消费设计系统 Token
1. 打开 AI Tab → 输入"帮我生成一个登录表单"
2. 在浏览器 DevTools 中检查发出的 system prompt 是否包含"设计系统 Token"段落
3. 检查 AI 返回的 HTML 代码块中是否使用 `var(--cc-primary)` 而非 `#1677ff`

### DS-02 验证：导入时提取设计特征
4. 导入一个含多种颜色和字号的 HTML 文件
5. 打开控制台 → `__CC.state.get('settings.designProfile')` 查看是否提取成功
6. 在 AI Tab 发送消息 → 检查 system prompt 中是否出现"项目风格参考"段落和高频颜色列表

### DS-03 验证：AI 输出设计质量检查
7. 故意让 AI 生成含硬编码颜色的 HTML（如 `color: #1677ff`）
8. 检查气泡中渲染的代码块是否被替换为 `color: var(--cc-primary)`
9. 点击"复制"按钮 → 复制的是清理后的 HTML（含 var() 引用）
10. 非代码块的文本不受影响（prose 中的 `#1677ff` 不被替换）
